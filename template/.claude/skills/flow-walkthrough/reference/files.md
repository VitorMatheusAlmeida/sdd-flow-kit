# Files of a walkthrough

All in the walkthrough folder (`<dir>`): `<feature>/<walkthrough.outputDir>` with spec-kit, else `<root>/<walkthrough.outputDir>`. JSON keys are in English; text values (names, messages) are in `project.locale`.

## `flows.json` — what each flow covers

```json
{
  "flows": {
    "R01": {
      "name": "Inscrever-se num curso",
      "screens": ["(public)/courses/**/page.tsx", "(app)/enrollments/page.tsx"],
      "exclude": ["**/admin/**"],
      "components": ["components/enrollments/**"],
      "controllers": ["enrollments/enrollments.controller.ts", "courses/courses.controller.ts"],
      "routeFilter": ["^GET /courses", "^POST /enrollments"],
      "publicRoutes": ["GET /courses/public/{course}"],
      "examples": { "course": "<slug of a published course>" }
    }
  }
}
```

| Key | Meaning |
|---|---|
| `name` | journey name (the one in the spec-kit script, when there is one) |
| `screens` | `next-app-router`: globs over `frontend.pages`. `manual`: list of routes, or `{ "route": "/x", "file": "relative to frontend.root" }` |
| `exclude` | globs taken out of `screens` and `components` |
| `components` | globs over `frontend.root`, added to the code scan |
| `controllers` | `nestjs`: controller files over `backend.root` |
| `routeFilter` | `nestjs`: regular expressions over `METHOD /path`; empty = every route of the controllers |
| `routes` | `manual` backend: list of `METHOD /path` |
| `publicRoutes` | routes `scan-api` calls without a session; `{var}` comes from `examples` |
| `examples` | values for the `{var}` of `publicRoutes` |

## `scenarios-<flow>.json` — the script layer

```json
{
  "name": "R01 — Inscrever-se num curso",
  "accounts": ["owner", "otherOwner", "member"],
  "owners": ["owner"],
  "fixed": { "course": "<id of a seed course>" },
  "setup": [
    { "as": "owner", "method": "POST", "path": "/courses", "body": { "title": "{prefix}Curso {rand}" }, "save": { "draft": "id", "slug": "slug" } }
  ],
  "calls": [
    { "name": "Detalhe", "method": "GET", "path": "/courses/{draft}", "parity": { "account": "otherOwner", "replace": { "draft": "{null}" } } },
    { "name": "Editar", "method": "PATCH", "path": "/courses/{draft}", "as": ["otherOwner", "member"], "body": { "title": "x" } },
    { "name": "Vitrine", "method": "GET", "path": "/courses/public/{slug}", "public": true }
  ],
  "screens": [{ "route": "/courses/{slug}", "as": ["owner", "otherOwner", "anonymous"] }],
  "cleanup": [{ "as": "owner", "method": "DELETE", "path": "/courses/{draft}" }]
}
```

- `accounts`: names from `accounts.roles` of `sdd.config.json` (default: all). `anonymous` always exists and has no session. Password: read it in `accounts.source` (the seed) and pass `--password`; `accounts.passwordEnv` or `accounts.password` exist for setups where the seed does not state it.
- `owners`: accounts with legitimate access; a success for another account becomes `foreign-2xx`. Per call with `owners`; `public: true` removes the alert.
- Variables: `{name}` (saved by `setup`, or from `fixed`), `{inDays:40}` / `{daysAgo:3}` (ISO dates), `{rand}` (unique suffix per run), `{prefix}` (`walkthrough.testDataPrefix`), `{null}` (an id that does not exist; `nullId` in the scenario changes it, e.g. `0` for numeric ids).
- `parity`: runs the call again as `account` with the variables of `replace` swapped, and compares status, code **and message** (fields from `backend.errorShape`). Different = the API reveals what exists.
- The order of `calls` matters: destructive ones (delete) go last.
- `screens`: route, accounts (`as`), optional `wait` (ms) and `maxHeight` (px). Widths: `walkthrough.viewports`, or `widths` in the scenario.
- A failed `setup` aborts (and runs `cleanup`) unless `--continue`.
- Limitation: JSON bodies only (file upload, `multipart`, stays in the manual pass).

### Alert codes

`scan-accounts`: `5xx`, `foreign-2xx`, `off-catalog` (4xx without the catalog code, or a raw framework message), `sensitive` (password, hash, document, token in the body), `slow` (> 2 s), parity that DIFFERS.

`scan-screens`: `horizontal-scroll`, `small-target` (< `minTouchTargetPx` on a phone), `covered`, `missing-accent`, `plural-with-1`, `title-case`, `garbage` (undefined, NaN), `repeated-text`, `toast`, `field-without-label`, `no-name`, `wrong-money`, `id-in-url`, `console-error`, `network-4xx/5xx`, `redirected(<url>)`, `not-found`.

Known false positives: `repeated-text` (the same data in sibling cards); `network-4xx` expected for a non-owner; `redirected(<sign-in>)` expected for `anonymous`; `not-found` expected for a non-owner.

## `matrix-<flow>.md` — generated by `inventory.mjs`

- Header with the **walkthrough** points (2, 3, 17, 18) and the line `Second walkthrough: ⏳` (localized), filled with the date.
- One `## Screen: /path` section per screen, with the screen points (1, 4–16) and the file.
- One `## Route: METHOD /path` section per route, with the route points (1, 10, 14, 15), the controller line and "Used by".
- **Status** column: `✅` (verified, with evidence), `🔧` (was wrong, fixed — evidence of the after), `n.a.` (does not apply — say why), `🚫` (out of scope by owner or project decision — say which), `⚠️ limitation` (impossible to simulate — say why). Empty or `⏳` = not done.
- `verify-matrix.mjs` fails with any empty or ⏳ cell, ✅/🔧 without evidence, `n.a.`/`🚫`/`⚠️` without justification, "from the code" as the only evidence, a section of something that left the code, or no date for the second round.
